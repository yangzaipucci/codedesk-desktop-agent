# CodeDesk：三个补丁与飞书 MCP 操作教程

适用版本：CodeDesk 1.2.0。资料核对日期：2026-11-03。

视频采用真实工作台关键画面、实际验收报告、中文合成语音和同步字幕；不是连续录屏。
本地 MCP 工具发现与调用、三个补丁的验收实际完成。飞书部分是配置教学，没有代替你登录、授权或读取真实飞书文档。

## 三个补丁的复查

1. 桌面右上角“模型与连接”，展开“技能、定制与常驻任务”。六个开关分别控制 A 技能与 B 规则/三类 hook/reviewer，以及 C 持久化任务。
2. 技能是流程。目录先注入，正文通过 read 按需加载。示例：`/skill code-review 审查当前项目，只报告可以复现的问题`。需要模型参与时使用桌面配置的 API。
3. 全局与项目 AGENTS.md 自动注入并限制长度；执行前拦截、修改后相关测试、任务结束只读审查。验收审查模型使用明确标注的受控 Provider，生产使用桌面模型。计量为 UTF-8 字节上界，不是厂商精确 tokenizer。
4. 持久化任务显式启动，不自动安装开机服务。验收会真的启动独立进程、前三步后强制终止、从第4步恢复。文件写入按哈希校验幂等；任意外部副作用不保证 exactly-once。
5. 在便携版 CodeDesk 运行目录执行：

```powershell
runtime\python.exe app\app.py inspect --output reports
```

源码方式为 `.venv\Scripts\python.exe app.py inspect --output reports`。报告按实际结果生成，不通过会返回非零退出码。

## MCP 与端口

CodeDesk 是 MCP 客户端，可连接本地 stdio 或 Streamable HTTP 服务。
stdio 通过子进程输入输出通信，无 TCP 端口；HTTP 接口与普通网页不同。
8877 是当前演示过的工作台网页端口；桌面版默认使用自动分配端口。
8001/mcp 是本项目另行启动的 HTTP MCP 默认接口，并需要独立连接令牌。
3000/callback 是飞书官方用户登录示例默认回调，不是飞书 stdio 的服务端口。

本地协议检查：设置 → MCP 外部工具 → 添加演示服务 → 保存 → 检查 MCP / 调用演示。
本视频实际完成了 1 个本地服务、1 个工具的发现与调用。本地成功不代表飞书授权成功。

## 飞书基础路线：官方 stdio + 应用身份 + 只读文档

1. 安装 Node.js LTS，重新打开终端，检查 `node -v`、`npm -v`。Windows 使用 `npx.cmd`。首次可执行 `npx.cmd -y @larksuiteoapi/lark-mcp --help` 预热，避免第一次下载超过客户端连接等待时间。
2. 在飞书开放平台创建应用，取得 App ID 与 App Secret，按所调用接口申请相应读取权限，让应用版本及权限在自己的组织中生效。只申请此演示需要的能力。
3. 应用身份访问非自有文档时，按官方云文档概述开启机器人能力，由文档所有者在目标文档中添加文档应用。接口权限和目标文档权限分别检查。
4. 在便携版 CodeDesk 运行目录打开 PowerShell，按“本机输入凭据与启动命令.txt”输入凭据并启动桌面。先退出旧窗口，从同一终端启动的程序才能继承本次 APP_ID、APP_SECRET。密钥通过隐藏输入提供，不写入源码、示例 JSON 或视频。环境变量仍是进程凭据，使用完成后关闭这次程序和终端。
5. 在“模型与连接”的 MCP 服务 JSON 框，合并“飞书MCP配置示例.json”中的服务对象。保留已有服务。CodeDesk 此处直接填写服务对象，不加最外层 `mcpServers`。示例只启用 `docx.v1.document.rawContent`，不启用消息发送、文档改写工具。
6. 视频输入框为尚未启用的示例（enabled=false）。配套 JSON 为使用模板（enabled=true），须先完成前述准备再启用。不要把 `${APP_SECRET}` 当成会自动展开的 JSON 值；本模板从启动进程环境继承凭据。
7. 保存后检查 MCP。工具能发现，不等于凭据及文档权限已经可用。选择 **Agent** 模式，接入有效的模型 Key，再让模型实际读取一篇已授权的新版 docx 文档并总结；以真实工具结果为准。目前 Ask/Plan 不加载自定义 MCP 服务。
8. 示例提问：“请先调用飞书读取工具，读取这篇已授权的新版文档，给出三点摘要。不要发送消息，不修改原文；失败时说明原因。”替换成你自己有权访问的链接或 document_id。

## 用户身份与远程 OAuth

必须以个人身份访问时，按官方 login 指引在本机完成 OAuth；回调示例为 `http://localhost:3000/callback`。完成官方登录后，按文档配置 `--oauth --token-mode user_access_token`。
CodeDesk 1.2.0 有 HTTP MCP 与连接令牌支持，但没有通用的浏览器 OAuth 授权向导；不能把远程 MCP URL 粘进去就宣称完成接入。飞书真实授权与真实数据调用尚未在本教程中完成。

## 常见问题

- 找不到 npx：检查 Node.js 安装与 PATH，并重启 CodeDesk，让它继承新环境。
- 连接失败或工具数量为0：检查 JSON、enabled、命令路径、首次下载、网络和进程是否继承了凭据。
- 工具已发现但读取失败：核对应用身份/用户身份、接口权限、应用版本和目标文档授权。wiki 节点 token 与 docx 文档 ID 不能直接混用；先从新版 docx 文档开始。
- 不能调用自定义飞书工具：当前版本使用 Agent 模式；Ask/Plan 不加载这些自定义服务。
- 模型能回答但没访问飞书：模型 Key 只授予模型调用；需看到飞书工具的真实执行结果才算数据链路通过。
